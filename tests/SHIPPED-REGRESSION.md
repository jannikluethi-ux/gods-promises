# Independent shipped-data and behavior regression

Historical baseline: `a0e3974474c07d121e7785d157dd331065d29d88:promises-data.js`.
The actual shipped file is at repository root, not `js/promises-data.js`.
Its SHA-256 is `bbfe7bb925ad3404e6ae06d4642e575d1a5a9598686eaedd82b24299aaf1781b`.

`test_shipped_regression.py` independently decodes the historical JS assignment as JSON,
without executing it and without obtaining expected data from `build_site.load_records`,
the WEB index, or any other builder transform. Actual output generation may call the builder;
expected data does not. Historical bytes are read with `git show` and verified against the
pinned hash in `fixtures/shipped-baseline.json`. In a shallow CI checkout, the unchanged
root shipped file is accepted only when its bytes match that same pinned historical hash;
otherwise the test fails and asks for the pinned commit rather than trusting regenerated data.
A separate test exercises acceptance/rejection of this shallow-checkout fallback.

## Result on the SEO branch

- Old shipped interactive entries: 1,188. New emitted interactive entries: 1,188.
- Added, removed or reordered IDs: 0.
- Changed references: 0. Changed WEB text strings: 0, byte-equivalent after JSON decoding.
- Changed themes, feelings or search-term arrays (including array order): 0.
- All 12 entry fields equal for every record: `id`, `reference`, `book`, `chapter`,
  `verseStart`, `verseEnd`, `promise`, `text`, `context`, `themes`, `searchTerms`, `feelings`.
- All 8 top-level metadata fields equal, including translation identity/note, vocabulary,
  schema version and coverage counts. Emitted JSON download also equals the old JS payload.
- All 1,188 static verse pages independently match the old shipped WEB text and reference.
  Their explanation text matches the current raw `data/explanations.json` directly, so the
  coordinated explanation-review branch can supply its latest approved wording.
- 13 auth/search/translation/privacy scripts are byte-identical to the historical baseline.
  Every emitted app/JS script and existing stylesheet is also byte-identical to the current
  release source. `ui-shared.js` deliberately is not pinned to the old commit, since the
  explanation-review branch may intentionally update its explanation cache-version constant;
  it must still copy byte-for-byte from that reviewed current release source to `dist`.

No interactive Scripture/data semantic differences are intended or observed. The emitted
JS's autogenerated comment/serialization is not a Scripture change. New static HTML,
metadata, directories, canonical/sitemap/robots output and migration stubs are intentional
additions; static explanations intentionally come from current reviewed data at every build.
Other translations remain the existing on-demand client feature, not prerendered replacements.

## Non-browser functional coverage

`behavior-regression.test.js` executes both source and emitted scripts in isolated Node VM
contexts using memory-only fake profiles/storage, real Web Crypto and stubbed fetch.
No actual account, browser, external API or real credential is involved.

- Auth: validation, signup, PBKDF2 hash storage without plaintext, duplicate/wrong/missing-user
  errors, normalized email, session persistence/reload, signout, auth observers/unsubscribe,
  favorites toggle/persistence and per-profile isolation.
- Search: 15 queries covering empty, themes, feelings, statements, reference, book and no-match,
  plus clarification. The full ordered matching IDs, ranking scores, relevance tiers/labels,
  and plans are identical before/after, using all 1,188 records as candidates.
- Translations: all 6 configured modes; exact offline WEB, on-demand requests for the other
  5 modes, coalesced requests, memory/session cache, selection/persistence/listeners,
  YLT Old Testament fallback and API-failure WEB fallback. API text is synthetic test data.
- Analytics: executes the actual queued `beforeSend` callback on allowed production hosts;
  every tested verse/browse path is dropped even with sensitive-looking synthetic query/hash
  values; allowed root strips those values. Preview/old-demo/localhost load no analytics script.

## Reproduce

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
node tests/analytics.test.js
node tests/safe-next.test.js
node tests/behavior-regression.test.js
git diff --check
```

The Python discovery run includes the behavioral Node test, so existing CI workflows already
run it without workflow edits. Run the builder first if invoking the standalone Node test
without first running Python discovery: `python3 scripts/build_site.py --target production`.

Independent historical identity check:

```sh
git show a0e3974474c07d121e7785d157dd331065d29d88:promises-data.js | sha256sum
```

This pinned migration regression intentionally fails for future catalog changes. Such changes
need explicit review and a deliberate baseline refresh; do not weaken it to compare the builder
against itself. Explanation-only reviews do not require a baseline refresh.
